# 可执行边界与等价回放范围

所有数值来自冻结输入快照 `data_version=degraded-ctd-irr-v1-64e0d9b08206`、
`semantics_version=v2-exante-execution`、`run_id=v2-base-20261119`，
`source_mode=degraded`，**条件化结论，不是市场结论**。

> 策略层的持仓标的、闸门与终值口径均采用**严格事前执行**语义：
> 持仓 = 结算日判定的期初 CTD，闸门与持仓同源；
> A 走现券市场退出、B/C 走实物交割退出，差额显式拆为估值基准差。
> 详见 `references/methodology.md` §8 与 `reports/AUDIT.md` §11。

## 1. 全成本带（正向 cash-and-carry）

| 项 | 值 | 口径 |
|----|----|------|
| 交易成本 + 滑点 | 0.5bp + 1.0bp | 按全价折算 0.0155 元/百元 |
| 交割费 | 0.02 元/百元 | 情景给定 |
| 价格成本合计 | 0.035504 元/百元 | `min_bnoc_to_cover_per_100` |
| 年化（28 天，ACT/365） | 44.778bp | 0.035504 / 103.36 × 365/28 |
| CTD 切换缓冲 | 5.0bp | `ctd_switch_buffer_bp` |
| **全成本带** | **49.778bp** | 年化 |

正向价差 `IRR − r = 34.737bp`（CTD = `SCEN-C`，IRR = 2.197%，r = 1.85%）。

> **判定：`forward_executable = False`**。账面净基差 `BNOC = −0.0287`（期货报价单位）
> 看似「便宜」，但覆盖不了融资 + 摩擦 + 交割费 + CTD 切换缓冲。
> 这是本题的核心可靠负结果：**账面偏差不是无风险套利**。

## 2. 反向腿（reverse cash-and-carry）

卖空现券 + 买期货需要债券借贷。借券费是**成本**不是收益；
本机与比赛接口均无卖空现券/借贷能力，因此 `reverse_executable = False`。
参考值 `reverse_spread_if_short_available_bp = −94.737bp`（已扣 60bp 借券费），
同样不支持可执行结论。

## 3. CTD 切换边界与静态安全垫

| 项 | 值 |
|----|----|
| 基准点前二名 IRR 安全垫 | 52.985bp（> 5bp 缓冲，静态判定安全） |
| 曲线平移切换边界 1 | **+5bp**：`SCEN-C → SCEN-A`（网格分辨率 10bp） |
| 曲线平移切换边界 2 | **+25bp**：`SCEN-A → SCEN-D` |
| 融资轴切换次数 | **0**（r 从 0.35% 扫到 4.85%） |

**关键结论**：静态安全垫 52.985bp 并不代表情景稳健——仅需 +5bp 曲线平移即发生 CTD 切换。
因此可执行判断必须做情景扫描，不能只看某一时点的 IRR 排序。

另一条可靠负结果：**融资变化不改变 CTD**（IRR 与 BNOC 两判据在整条 r 网格上均稳定），
融资变化只改变**成本覆盖门槛**与净基差大小。把「融资变化」与「CTD 切换」混为一谈是错的。

### 3.1 事前口径下的 CTD 切换暴露（v2 新增）

严格事前持有期初 CTD 后，CTD 切换不再是隐含在持仓里的东西，而是**可量化的风险**：

| 指标 | 冻结基线 | 官方锚定 |
|---|---|---|
| 事后最优券已不是持仓券的情景 | **190 / 399（47.6%）** | 171 / 399（42.9%） |
| 事后机会成本均值 | **1259.09bp** | 1296.52bp |
| 事后机会成本最大 | 2965.07bp | 2750.95bp |
| 事后换券反事实 P&L 变化（均值 / 区间） | +0.127906 / +0.000000 ~ +1.968208 | +0.332542 / **−0.067883** ~ +1.787725 |

反事实**不可实现**，且**不是上界**（IRR 更高的券其 CF 可能更低，绝对 P&L 反而更小，
故差额可正可负）。它的作用是给「交割期权」一个可量化的风险刻度，
不得据此声称测得期权价值。

## 4. 转换因子敏感性（最硬的边界）

`robustness.json` 二分求解：**使正向可执行判定翻转的最小 CF 平移 = 0.00011112**。

传导：CF 平移 δ → 发票价上升 `F·δ` → IRR 年化放大 `365/d ≈ 13` 倍 →
本快照距成本覆盖仅 15.04bp，故 1.1e-4 的 CF 变动即翻转结论。
交易所公布 CF 通常给到 4 位小数，因此：

> **缺交易所公布 CF 时，一律不得给出可执行结论。**
> 这正是题目「缺券价或交割条件时须缩小范围」与
> 「不把账面偏差直接称为无风险套利」的量化依据。

微扰检验另有 9 项：成本 ±10%、r ±0.0002、缓冲 ±2bp、期货价 ±0.01 下
CTD 与正向可执行判定均不翻转；仅 CF ±0.0005 触发翻转并已单独解释，
`conclusion_stable = True`（成本/价格类）+ `cf_sensitivity_alert = True`。

## 5. 容量边界（对标原 Q7 最高档口径）

| 约束 | 值（万元面值） |
|------|----------------|
| 可交割券存量合计 | 420,000 |
| 可借券存量合计 | 88,000（**反向腿约束，不进入正向 binding**） |
| 单账户限仓折算 | 200,000 |
| 绑定上限 | **200,000（position_limit）** |
| 按 5% 参与率的可执行名义 | 10,000 |

算法：可交割券存量与单账户限仓取最小，并标注约束名。**借券存量不参与正向 binding**：
正向 cash-and-carry 是「买现券 + 卖期货」，不占用借券额度；借券是反向腿（卖空现券）的
约束，而反向腿在本项目判定为不可执行。冻结产物记录的旧值为 88,000（约束项
`lendable_stock`），属修复前口径，见 `reports/AUDIT.md` §10 表 C-3。
容量参数同为情景给定，不是交易所限仓或真实存量；
本 skill 交付的是**口径与算法**，不是真实容量数字。

## 6. 为什么不把账面偏差称为无风险套利

1. CTD 可切换：空头持有交割期权，净基差不等于零不等于可锁定利润。
2. 交割结算价由交易所规则产生，不能用当前期货价代理后宣称已锁定。
3. 现券买卖价差、借券可得性与回购利率浮动未逐笔建模。
4. 转换因子与交割日历为情景给定/参考值，非交易所公布值（见 §4 敏感性）。
5. `input_origin = declared_scenario`，`market_conclusion = false`。

## 7. 期货模拟赛核验与「等价回放范围」（事先声明）

题目条款：交易执行部分用期货模拟赛核验；品种或接口不支持时**事先明确**等价回放范围。
本声明写在 `contest_scope.json`（`declared_before_run = true`），先于任何执行。

**只读平台探测（2026-11-14）**：

| 项 | 事实 |
|----|------|
| 平台真实入口 | `QSHome/launch-quantskills.ps1` → `launcher.mjs` → `dsh web: 127.0.0.1:3097/`；本次实际启动并 HTTP 200 核验 |
| 品种目录 | 含中金所 `t/tf/ts/tl`，`enabled=true`；但目录不保证具体交割月份有行情或开放交易 |
| 比赛 CLI | `QSHome/quantskills/contest/` 不存在，`state.json`/`auth/`/`runtimes/` 均无 → `cli_available=false` |
| 实际委托 | `live_order=false`，未安装 CLI、未登录、未发出任何委托 |

**可核验范围**（条件满足时）：期货腿的合约有效性、最新报价、`order --dry-run` 预演、
持仓与成交回执。官方 CLI 参数形状：
`node <runtime>/node_modules/@chongqingliangyunzhijing/contest-cli/bin/panda.js order --symbol <contract> --direction sell --offset open --volume <lots> --dry-run --json`。

**不可核验范围**：可交割券清单与现券全价、应计利息与票息现金流、转换因子、
发票价格与实物交割、债券借贷/借券成本、交割结算价形成规则。
原因：模拟赛只提供期货单腿行情/委托/成交接口（`docs/contest.md`），不含现券与交割域。

**等价回放范围（in scope）**：按 CTD 与对冲比率生成期货腿 dry-run 计划参数；
按冻结输入快照的确定性账本回放期货腿 P&L；融资、CTD 切换、成本覆盖与容量边界的情景复算。

**等价回放范围（out of scope）**：真实委托/成交回执/资金持仓变动；
现券成交、实物交割、发票价结算、借券失败处理；把回放账本称为成交记录或实盘核验。

产物：`contest_replay/contest_scope.json`、`dry_run_plan.json`（`status=PLAN_ONLY_NOT_SUBMITTED`）、
`replay_ledger.csv`（每行 `ledger_type=deterministic_offline_replay_not_exchange_fill`）。

## 8. 失败边界

- 输入契约失败 → 退出码 2，不产出报告。
- 公式恒等式破坏 → `AssertionError`，不出报告。
- 比赛 CLI 未授权 / 无行情 → 只保留等价回放，不补造回执。
- 缺交易所公布 CF / 官方交割日历 → 结论降级为方法复现，不给可执行结论。
- 情景是参数网格，不是历史时间序列；所有 P&L 为条件结果，不是收益预期。

## 9. 官方行情锚定后的边界收紧（2026-11-14 补充）

`run_id=v2-anchor-20261119` 把 `T2612.CFE` 官方结算价 110.05 与真实交割窗口
2026-12-14~16 换进同一份声明式篮子，其余字段一字未改。结果：

> 下表为**当前口径（v2）**，完整登记见 `reports/AUDIT.md` §11。
> v1 历史 run 的对应数值（跳过 179 个等）保留在原路径，仅作口径对照。

| 判据 | 冻结基线 | 官方锚定 |
|---|---|---|
| `IRR−r` | 34.737bp | **3019.41bp** |
| 全成本带 | 49.778bp | 45.44bp |
| `forward_executable` | False | **True** |
| C 跳过情景 | **273/399** | **0/399** |
| CF 翻转阈值 | 0.00011112（告警开） | 0.005（告警关） |

**判定：该 `True` 无效**。真实期货价配 1.85% 收益率曲线折现出的声明式现券，
两者不在同一市场状态，2.73 元报价差被年化成虚假基差，直接把全成本覆盖、
CTD 缓冲两道闸门全部打开；CF 敏感性告警消失也只是因为微小 CF 变动
已无法抵消巨额虚假价差，不是约束变松了。

因此本题可执行边界的最终口径为：

> **只有同时具备** ①交易所公布可交割券清单 ②现券全价/应计与票息现金流
> ③交易所公布 CF ④市场回购与借券成本 ⑤真实交割结算价规则，
> **且它们与期货行情处于同一 `as_of`**，才允许输出 `forward_executable` 判定。
> 缺任一项，即使期货行情来自官方数据库，也必须输出「不可判定」并保留 `degraded`。

官方库实测覆盖期货行情与合约静态条款（159 个 Government 合约、真实交割窗口、
结算价、乘数/保证金率），但**不覆盖 ①②③④中的任何一项，也不提供 ⑤ 的交割结算价
形成规则**（`get_future_detail` 只给交割起止日）；`get_macro_ir` 的 829461 行指标
缺码表文件，不能当作回购利率。逐方法排除依据见 `data/official/coverage_probe.json`。

### 机器可读的无效标记

仅靠 `report.md` 的 L1 文字告警不足以约束下游：`executable_boundary.json`、
发布态快照与 `strategy_comparison.csv` 都可能带 `forward_executable=True`。
`runtime/scenarios.py` 在边界产物里强制写三个字段，门禁逐项校验：

| 字段 | 冻结基线 | 官方锚定 run | 含义 |
|---|---|---|---|
| `verdict_status` | `CONDITIONAL_VALID` | **`INVALID_MIXED_STATE`** | 判定状态 |
| `conclusion_valid` | `true` | **`false`** | 结论是否可用 |
| `forward_executable_usable` | `true` | **`false`** | 下游能否据此下交易/研究决策 |

`invalidated_by` 数组在混合 run 里逐条给出无效原因；`forward_executable` 的原始
数值**保留不篡改**（它是可复算的计算结果），但不得被解释为可执行。
下游消费顺序：先读 `verdict_status` / `conclusion_valid` / `forward_executable_usable`，
三者通过后才读 `forward_executable`。
